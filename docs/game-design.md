# 《流形迴響》遊戲設計文件（GDD）

- 英文名稱：**MANIFOLD ECHOES**
- 文件版本：0.1（初版設計基準）
- 狀態：設計草案，待原型驗證
- 專案定位：以生存射擊為核心，融合可操控幾何空間與玩家行為塑造能力的俯視角遊戲。

> 你如何穿越這個世界，世界便如何回應你。

## 1. 核心概念

《流形迴響》是一款俯視角、即時生存射擊遊戲。玩家在一個由幾何結構與流動形體構成、彷彿具有生命的空間中生存十分钟。

玩家只有一種武器：**子彈**。子彈會自動發射，遊戲深度來自子彈特性、玩家移動方式，以及玩家對戰場方塊與空間規則的運用。

遊戲會持續觀察玩家的實際玩法。玩家經常與敵人保持距離、貼近敵人作戰、頻繁移動、繞行、承受傷害，或利用方塊改變子彈路徑，都會影響升級時不同強化卡片的出現權重。

核心特色：
1. **空間會回應玩家：** 部分方塊固定，部分方塊可由玩家操控；特殊空間規則會改變移動與子彈路徑。
2. **行為塑造流派：** 不需預先選擇職業，遊戲依玩家近期行為調整強化卡片出現機率。
3. **單一武器、多種演化：** 所有攻擊均以子彈為基礎，強化改變子彈的數量、速度、路徑與命中效果。

## 2. 目標平台與操作

- 目標平台：電腦與手機，採響應式操作與介面。
- 電腦：WASD／方向鍵移動。
- 手機：虛擬搖桿移動。
- 子彈自動發射；玩家主要負責移動、閃避、操控空間及選擇強化卡片。
- 升級選卡時暫停戰鬥，選擇後繼續。

## 3. 核心遊戲循環

1. 進入單一戰場。
2. 敵人持續從戰場周圍出現。
3. 玩家移動、閃避並以自動發射的子彈攻擊敵人。
4. 擊敗敵人取得經驗／能量。
5. 升級時顯示強化卡片供玩家選擇；卡片出現權重受玩家行為影響。
6. 敵人隨時間增強，戰場空間與敵人組合逐步增加壓力。
7. 在十分钟戰鬥流程末段迎戰 Boss。
8. 戰敗或勝利後結算，保存本機紀錄。

## 4. 武器與子彈系統

### 4.1 唯一武器

遊戲只有一種武器：**子彈**。不設置刀劍、雷射槍、炸彈等其他武器類別。

### 4.2 子彈可演化的方向

- 數量：一次發射更多子彈。
- 速度：提高飛行速度。
- 射程：延長有效飛行距離。
- 穿透：命中後繼續穿過敵人。
- 散射：向多個方向發射。
- 追蹤：飛行途中修正方向。
- 反彈：碰撞特定方塊後改變方向。
- 回旋：飛出後沿路徑返回。
- 曲線：沿弧線或其他特殊軌跡飛行。
- 空間穿越：經過特殊空間連接點後從另一處出現。

以上是子彈的強化維度，不代表初版必須全部實作；初版以十二張強化卡片為範圍。

## 5. 玩家行為分析與強化卡片

### 5.1 設計原則

遊戲持續記錄玩家行為，並將分析結果轉換成強化卡片的**出現權重**。例如：
- 長時間與敵人保持距離，遠程類卡片權重提高。
- 經常貼近敵人，近距離類卡片權重提高。
- 移動頻繁或經常改變方向，機動與軌跡類卡片權重提高。
- 受傷頻率偏高，防禦、閃避或恢復相關卡片權重提高。
- 經常利用或操控方塊，空間類卡片權重提高。

**行為只影響卡片出現機率，不鎖死卡池，也不強制玩家維持某一種流派。** 玩家改變玩法後，卡片權重應能逐步跟著改變。

建議以近期行為窗口計算權重，避免整場早期行為永久主導後續選卡。窗口長度、權重公式與保底機制留待原型測試調整。

### 5.2 觀察指標

| 行為指標 | 可衍生的卡片方向 |
| --- | --- |
| 與敵人的平均距離／距離分布 | 遠程、近距離 |
| 移動頻率與移動時間比例 | 機動、移動增益 |
| 移動軌跡（直線、迴旋、環繞、頻繁轉向） | 軌跡、曲線子彈 |
| 受傷頻率與受傷間隔 | 防禦、閃避、恢復 |
| 子彈命中時的距離 | 精準、近距離爆發 |
| 子彈反彈後命中次數 | 反射、空間強化 |
| 經由傳送／空間連接命中的次數 | 空間穿越 |
| 推動、旋轉或改變方塊的頻率 | 地形與空間操控 |
| 靜止時間比例 | 定點、防禦或蓄力方向 |

以下為初版候選卡片，數值與效果仍待平衡測試。

| 分類 | 卡片 | 初步效果 |
| --- | --- | --- |
| 遠程 | 長程彈道 | 增加子彈射程 |
| 遠程 | 高速彈頭 | 增加子彈速度 |
| 遠程 | 穿透彈頭 | 子彈可穿透敵人 |
| 近距離 | 散射彈頭 | 一次向多個方向發射子彈 |

| 近距離 | 近距離增幅 | 子彈在近距離造成更高傷害 |

## 6. 戰場與空間規則

### 6.1 戰場原則

- 初版只有一張戰場。
- 戰場由幾何方塊、流動形體與特殊空間結構構成。
- 空間不是靜態背景，而是玩家走位、攻防與子彈路徑策略的一部分。
- 視覺上避免冰冷軍事基地風格，強調「幾何與流動形體融合，空間像活著一樣」。

### 6.2 方塊類型

1. **固定方塊：** 構成戰場基本結構，不可由玩家移動。
2. **可操控方塊：** 玩家能推動、旋轉或以其他明確方式改變其位置／狀態，用來創造路線、阻隔敵人或改變子彈路徑。
3. **特殊空間結構：** 以空間規則改變物件或子彈的移動方式，例如反射、折射、傳送或局部空間變化。

初版具體可操控方式、操作成本、方塊數量、互動限制與特殊規則清單尚待原型設計。

## 7. 敵人設計

### 7.1 普通敵人（三種）

1. **追獵者：** 持續追逐玩家，迫使玩家移動。
2. **疾行者：** 移動速度快、生命值低，擅長快速接近玩家。
3. **重裝者：** 移動緩慢、生命值與防禦較高，壓縮玩家的活動空間。

### 7.2 Boss（一種）

**裂隙核心守衛（暫定名稱）**

Boss 不只具備較高生命值，也會干涉戰場空間，例如：
- 改變部分方塊狀態或方向。
- 產生空間連接區。
- 暫時改變子彈反射／折射規則。
- 隨戰鬥進程壓縮安全活動區域。

實際攻擊模式、階段與數值待設計。

## 9. 美術方向與色彩規範

### 9.1 美術定位

**有機幾何（Organic Geometry）**：幾何結構與流動形體融合，空間彷彿具有生命。

視覺方向：
- 方塊可保留幾何辨識度，但輪廓可圓潤、變形或具有有機起伏。
- 固定方塊像世界的骨架；可操控方塊像會回應玩家的器官。
- 空間連接處呈現脈動、呼吸或漣漪感。
- 子彈飛行留下短暫軌跡，玩家行為可透過視覺回饋與世界產生「迴響」。
- 避免厚重軍事裝甲、傳統戰爭基地與過度寫實的武器美術。

### 9.2 僅允許使用的七種顏色

以下七色為硬性限制，所有 UI、角色、敵人、場景、方塊、粒子、特效、陰影與文字皆須遵守，不得引入第八種色相。

| 色彩 | HEX | 建議用途 |
| --- | --- | --- |
| 藍 | `#5D81C7` | 玩家、子彈、主要互動 |
| 深藍 | `#37339D` | 戰場深色、空間背景 |
| 淺藍 | `#9CC9D9` | 能量、空間特效、流動亮部 |
| 紅 | `#BE4449` | 敵人、危險、傷害提示 |
| 灰 | `#B3B3B3` | 方塊、機械、結構 |
| 白 | `#F3F3F3` | 文字、亮部、資訊 |
| 深灰 | `#333333` | 輪廓、介面、暗部 |

漸層只可由上述色票中的顏色組成。透明度、混色、陰影、瀏覽器原生控件與特效需特別檢查，避免視覺上產生未經允許的顏色；實作時應集中管理色票變數。

## 10. 本機紀錄

- 初版支援本機存檔。
- 保存內容至少包含可持續的遊戲紀錄／統計。
- 存檔格式、資料版本、清除紀錄方式與使用的瀏覽器儲存機制待技術設計確認。

## 11. 尚待原型驗證與決策

以下項目不視為已定案：
1. 玩家與子彈的基礎數值、攻擊目標選擇方式與自動射擊節奏。
2. 行為分析窗口長度、權重公式、卡片抽取規則與避免流派鎖死的保底機制。
3. 十二張卡片的具體數值、升級上限、重複取得規則與平衡。
4. 可操控方塊的操作方式、成本、限制與可操控數量。
5. 特殊空間規則的完整清單及其對玩家、敵人、子彈的作用範圍。
6. 十分鐘內的敵人生成曲線、升級頻率與 Boss 出場時間。
7. Boss 階段、攻擊模式與戰場干涉方式。
8. 本機存檔技術與跨裝置資料是否完全獨立。

## 12. 開發原則

- 先建立可遊玩的最小原型，優先驗證移動、子彈、自動攻擊、敵人、方塊互動與行為分析。
- 以模組化方式分離資料模型、UI、運算與世界場景。
- 每次修改採獨立分支，依專案既定流程進行 Preview、瀏覽器驗收與人工驗收；未經主人同意不合併。
- 設計文件中的候選方案需經原型測試後才能標記為正式規格。
